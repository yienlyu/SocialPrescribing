# 社會處方・B 共同擬定處方（虛擬 Link Worker）

醫學人文課程作品。以 CUSP 框架（Muhl et al., 2023；2024）中的 **B：共同擬定處方** 為主題，
以團隊蒐集、臺北實際存在的社會處方為資源，服務對象為社區居民（各年齡層的當事人與照顧者）。
網站扮演虛擬 link worker：接收第一組（A 識別需求）轉介來的居民，透過對話共同擬定處方，
最後產出處方籤與轉介單，refer 到資源端（C）。

## 功能
- **身份分流**：進站先選「民眾」或「專業人員」，兩邊看到不同的首頁與功能，右上角可隨時切換
- **民眾：我的處方**：掃處方籤 QR code（或輸入編號＋取件碼）查看處方、出示報到用 QR code、填近況問卷、看「我的改變」；可註冊帳號並綁定處方
- **民眾：我有興趣**：在社區處方庫標記想試試的活動，右下角按鈕隨時打開清單；可產生 QR code／連結給 link worker，對方打開後媒合結果會標出「♡ 有興趣」並略為加分。登入後清單存在帳號（Supabase user metadata）
- **專業人員：候選處方**：右下角按鈕隨時看到目前候選（最多 3 項）與當事人有興趣的活動，一鍵回到工作台
- **工作人員自行註冊**：link worker／社工與資源端工作人員可以自己註冊，輸入管理者給的開通碼即開通；資源端註冊時自己勾選負責的活動，之後也能修改
- **資源端：現場報到**：活動現場工作人員登入後掃當事人的 QR code，確認身分後幫他報到（只限自己負責的活動）
- **專業人員：個案追蹤**：登入後看所有處方的報到率（含由誰報到）、前後測變化（ONS4＋UCLA 孤寂感）、該追蹤的個案，可用編號查詢、電話追蹤代填
- **居住地與可近性**：以臺北 12 個行政區估算到每個處方的大眾運輸時間（粗估），納入媒合計分（行動不便、無人接送、75 歲以上加重）；處方庫可選「我住在…」並篩選 30 分鐘內；限設籍臺北市的方案會提醒資格
- **雲端後端**：Supabase，設定步驟見 [`supabase/README.md`](supabase/README.md)；未設定時其餘功能照常運作
- **Healthy People 2030**：介紹健康的社會決定因素（SDOH）五大領域，並對應到本站的需求選項與處方分類；處方籤會自動標出回應了哪幾個領域（對應表在 `data.js` 的 `SP.HP2030`）
- **處方工作台**（5 步）：接收轉介 → 對話（What matters to you?）→ 媒合地圖 → 共同決定 → 處方籤／轉介單。專業人員版首頁一進來就是工作台，理論背景（我們的位置、Healthy People 2030、共同擬定原則、回饋迴圈）移到後面
- **當事人確認**：共同決定時逐項問「這是你想試試的嗎？」（✓ 我想試試／✕ 先不要，選先不要直接移除）；開立前跳出白話摘要念給當事人聽，由當事人輸入名字簽名，處方籤記錄確認日期；之後改了內容需重新確認
- **照顧者模式**：民眾選「為了家人」時，處方庫上方出現「照顧別人，也要照顧自己」專區，「我的處方」底部提醒照顧者自己的喘息資源；問卷、報到卡等用字改為「他」
- **轉介連結**：第一組在「對話」步驟填好需求後按「複製轉介連結」，連結打開就會帶入該位居民
- **社區處方庫**：實際存在的處方，依 9 類篩選、關鍵字搜尋，每張附場域、對象、提供單位與原始連結，可直接放進候選
- 列印處方籤（存到雲端後附 QR code 與取件碼）、複製轉介文字；工作台草稿只存在瀏覽器 localStorage

## 檔案
- `index.html` 頁面結構與文案
- `styles.css` 視覺樣式（延續論文資訊圖表的米白／墨黑／朱紅）
- `data.js` 需求、興趣、阻礙、處方資料、示範居民（要改內容改這裡）
- `app.js` 互動與媒合計分邏輯
- `portal.js` 身份分流、登入、雲端存檔、QR 報到、量表與進步圖、個案追蹤
- `config.js` Supabase 連線設定
- `supabase/schema.sql` 資料表、權限規則與民眾端函式

純靜態網站，無需建置。本機預覽：`python3 -m http.server`，打開 http://localhost:8000
